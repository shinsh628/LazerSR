## 1. 바닐라 mania SR 계산 구조 (코드 단위)

### 1.1 파이프라인
1. `ManiaDifficultyCalculator.CreateDifficultyHitObjects` — 노트를 반올림한 시작 시각으로 정렬(`LegacySortHelper`). **두 번째 노트부터** 난이도 오브젝트가 된다 (첫 오브젝트는 이전 노트 목록에 들어가지 않음).
2. `ManiaDifficultyHitObject` — 열, 같은 열 직전 노트와의 간격(`ColumnStrainTime`), 열별 "가장 최근 처리된 노트" 배열(`PreviousHitObjects`)을 들고 있다.
3. `Skills/Strain.cs` — 노트마다 스트레인 `S = H + O`를 갱신.
4. `StrainSkill` — 400ms 구간마다 최대 S(피크)를 저장, 내림차순 정렬 후 0.9ⁿ 가중합.
5. **SR = 가중합 × 0.018**

### 1.2 노트 하나의 계산
- **H (열 개별 스트레인)**: 그 열의 값 × `0.125^(ColumnStrainTime/1000)` + `2.0 × holdFactor`. 동시치기(`DeltaTime ≤ 1`)는 열 최댓값 사용.
- **O (전체 스트레인)**: 이전 값 × `0.30^(DeltaTime/1000)` + `(1 + holdAddition) × holdFactor`. 초기값 1.
- **holdFactor = 1.25**: 이전 노트 p가 `p.End > end` 이고 `start > p.Start` (현재 노트가 p 안에 들어감).
- **holdAddition = Logistic(closestEndTime, 중심 30, 기울기 0.27)**: 겹침 조건(`p.End > start`, `end > p.End`, `start > p.Start`)을 만족하는 p가 있을 때만.
  - `closestEndTime = min(현재 노트 길이, |end − p.End| for 모든 PreviousHitObjects)`
- 모든 비교는 `Precision.DefinitelyBigger(a, b, 1)` = **a − 1 > b** (1ms 초과). 재현 검증으로 확인.

### 1.3 자주 틀리기 쉬운 성질 (실측 확인)
- **나중에 시작한 노트만 손해**: 판정은 "이미 처리된 노트"만 본다. 릴리즈가 가까운 두 노트 중 먼저 시작한 쪽은 영향이 없다.
- **탭과 이미 끝난 롱노트는 홀드어디션을 깎지 않는다**: p가 먼저 시작했으므로 `|end − p.End| ≥ 현재 노트 길이`. 실제로 깎는 것은 "현재 노트가 시작하는 순간 눌려 있는 롱노트"의 릴리즈뿐이다. (대화 초반에 "탭이 깎는다"고 한 설명은 틀렸고 정정함)
- **첫 오브젝트 함정**: 덮개(긴 롱노트)가 맵의 첫 노트면 홀드팩터가 전부 사라진다. 실측 10.84 → 8.67.
- **롱노트 길이 자체는 무관**: 조건만 만족하면 길이를 바꿔도 SR이 소수점 4자리까지 같다.
- **열 순서는 무관**: 계산이 열 배치에 대칭이다.

## 2. 단순화 수학 모델

### 2.1 정의
- 줄(열) 4개에 구간 [s, e]를 놓는다. 같은 줄 구간끼리 겹침 금지, 같은 줄 시작 간격 ≥ 125ms.
- 구간 X는 시작 순간 한 번 점수 **v = (1 + a) · f** 를 받는다. "선배" = X보다 먼저 시작했고 X 시작 순간 아직 눌린 다른 줄 구간.
  - f = 1.25 (선배가 X를 완전히 감쌀 때), 아니면 1
  - a = σ(d) (선배의 끝점이 X 몸통 안에 있을 때), 아니면 0
  - d = min(X 길이, X 끝점과 각 선배 끝점의 거리)
  - σ(d) = 1 / (1 + e^(0.27·(30 − d))) → σ(20)=0.06, σ(30)=0.5, σ(45)≈0.98
- **SR ≈ 0.18 × (O + H)**, 균일 반복 시 O ≈ R / 1.2 (R = 초당 Σv), H ≈ 2f / (1 − 0.125^Δ) (Δ = 열 간격 초)

### 2.2 검산
| 배치 | R | 예측 SR | 실측 SR |
|---|---|---|---|
| E4 | 62.8 | 11.4 | 11.62 |
| b (덮개 + 3열 롤) | 58.3 | 10.7 | 10.84 |
| 4열 탭 32nps | 32.0 | 6.4 | 6.41 |

모델은 "시작 몰림" 효과(O 피크 상승)를 포함하지 않아 E4를 약 2% 낮게 예측한다.

### 2.3 릴리즈 간격 예산 (핵심 원리)
- 열당 8kps로 4열을 채우면 126ms마다 릴리즈 4개 → 릴리즈 간격 평균 31.5ms. 총량은 고정.
- 이웃 릴리즈 간격 하나의 비용은 **나중에 시작한 쪽 하나만** 낸다(d ≤ 간격).
- 노트는 간격 비용을 0, 1, 2개 낸다. 2개를 내는 노트는 위쪽 이웃이 자기를 감싸므로 **홀드팩터가 자동으로 붙는다**.
- 4열 롤: 4노트가 1개씩 → 모두 σ(31) ≈ 0.57~0.63, 주기당 O 합 6.38
- **E4**: 긴 노트 2개는 0개(σ≈1.0), 짧은 노트 2개가 2개씩(σ≈0.57 + 홀드팩터) → 주기당 O 합 7.91 (모델 최대 8.0의 99%)

### 2.4 수학적 최적/상한
- **4구간 주기(열당 1개) 최적**: R = 63.479 @ 126ms (40회 독립 탐색이 모두 동일 값으로 수렴, 형식적 증명은 아님). 연속 시간이면 125ms, 간격 31.25ms에서 63.67.
- **비주기 추정 최대**: R ≈ n·(1 + 0.625·(1 + σ(1000/n))), n ≤ 32 → **63.7**
- **비주기 증명된 상한**: R ≤ 1.25·n·(1.5 + 0.5·σ(1000/n)) → **71.7** (모든 구간이 홀드팩터를 받는다고 후하게 가정한 약한 천장. 달성 가능성은 모름)
- 열린 문제: "간격 비용을 안 떠안는 구간도 홀드팩터를 받을 수 있는가" — 증명/반례 시 63.7~71.7 사이가 확정됨.

## 5. kps 스윕 (E4 구조를 비례 축소·확대)

### 5.1 곡선 공식 (k = 열당 kps)
```
SR(k) ≈ 0.18 × [ k·( 2·(1+σ(500/k)) + 2.5·(1+σ(250/k)) ) / 1.2  +  2.5 / (1 − 0.125^(1/k)) ]
```
500/k = 긴 노트의 간격(주기/2), 250/k = 희생 노트의 간격(주기/4). 실측과 최대 5% 차이.

### 5.2 측정값
| 열당 kps | SR (E4) | 긴 노트 홀드어디션 | 희생 노트 홀드어디션 |
|---|---|---|---|
| 5.00 | 8.39 | 1.000 | 0.992 |
| 6.25 | 10.14 | 1.000 | 0.919 |
| 7.94 | 11.62 | 1.000 | 0.567 |
| 9.09 | 12.32 | 0.999 | 0.308 |
| 10.00 | 13.09 | 0.996 | 0.206 |
| 10.42 | 13.45 | 0.992 | 0.165 |
| 12.50 | 15.26 | 0.937 | 0.049 |
| 16.67 | 17.76 | 0.500 | 0.013 |

### 5.3 해석
- 긴 노트 1.0 유지 한계: 0.999 기준 약 9.1kps, 0.99 기준 약 10.4kps.
- SR은 계속 오르지만 **kps당 이득은 골짜기 모양**: ~6kps 이하 약 1.5 → 6.25kps부터 급락 → **8.2kps에서 최저(약 0.5)** → 11.5kps 근처 약 0.9로 회복 → 12.5kps부터 다시 하락.
- 평균 효율(SR/kps)은 단조 감소라 내부 최적점이 없다.
- **열당 8kps 제한은 이 구조에서 가장 비효율적인 지점**에 걸려 있다.

## 6. SR 극대화 규칙 (중요도 순)

### A. 반드시 지킬 것
1. **열당 상한까지 노트를 채우고 빈 구간을 만들지 마라.** (노트 수가 곧 점수, 공백 손실은 약 1초 남음)
2. **모든 노트를 롱노트로, 홀드어디션 조건을 걸어라.** (탭 6.41 → 롱노트 롤 9.23, +44%)
3. **릴리즈 간격 예산을 비대칭으로 써라.** 절반은 비용 0(홀드어디션 1.0), 절반이 비용을 몰아서 떠안고 홀드팩터를 받는다. (롤 9.23 → E4 11.62)
4. **짧은 노트를 다른 열 긴 노트 안에 넣어라.** (×1.25, O와 H 모두)
5. **노트 시작을 몰아라.** (E4 11.62 → 묶음 동시치기형 12.03, +3.5%)

### B. 함정
6. 덮개가 맵의 첫 노트면 안 된다 (−20%).
7. 모든 판정은 1ms 초과 조건 — 엇갈림은 2ms 이상.
8. 동시치기(시작 차이 1ms 이내)는 홀드어디션을 못 받는다.
9. 고난도 구간은 8~12초 이상 유지 (상위 20~30개 구간이 90% 이상 결정).

### C. 신경 쓰지 않아도 되는 것
- 롱노트 길이 자체, 열 순서, 탭/이미 끝난 노트의 위치.

### D. 기각된 아이디어
- 무한 덮개 + 예산 나누기: 덮개 열의 밀도 손실(초당 8노트)이 더 큼. 최대 주기당 7.5 < E4 7.91.
- 폭발 배치: 공백 손실 > 폭발 이득 (3.4절).
- "E4가 천장"이라는 중간 판단은 틀렸음 — 시작 몰림 효과를 놓쳤고, 탐색이 12.03을 찾음.

| 왼손 | 긴 | 슬롯 0 | 슬롯 3 |
| 왼손 | 짧은 | 슬롯 0 + 2ms | 슬롯 2 |
| 오른손 | 긴 | 슬롯 2 | 슬롯 5 |
| 오른손 | 짧은 | 슬롯 2 + 2ms | 슬롯 4 |

- 4슬롯마다 반복, 릴리즈가 1슬롯 간격 → E4 구조와 정확히 일치.
- **열당 kps = bpm / 30** (bpm 238 ≈ E4 126ms, bpm 240 = 열당 8kps). 다른 bpm은 5장의 곡선을 따른다.
- 묶음 동시치기형(11ms 간격 필요)은 격자 + 2ms 예외로 표현 불가.

### 7.3 필요한 변경
1. **`SlotState`에 롱노트 표현 추가** — 시작/몸통(열 점유)/끝.
2. **마디 경계를 넘는 롱노트** — 오른손 긴 노트(3슬롯)는 마디 마지막 묶음(슬롯 30)에서 슬롯 33으로 넘어감. 위상을 바꿔도 하나는 항상 넘어가므로 데이터 구조가 이를 받아야 함.
3. **주입기 2곳에서 `HoldNote` 생성** — `TrainingSequencer.inject`, `SyntheticPatternMap.Build`. 길이 = 끝 격자 시각 − 실제 시작 시각 (시작을 2ms 늦춰도 릴리즈는 격자 유지).
4. **2ms 예외** — "늦게 누르는 노트" 표시용 `SlotState` 값 1개 + 주입기마다 시작 시각 `+2ms` 한 줄 (주입기 2곳 → 2줄).
5. **새 생성기 클래스 + `PatternCatalog` 등록.**
6. **연동 확인** — `ColumnMask`/`ReadTailMasks`(마디 경계 열 회피)가 롱노트 몸통 점유를 반영하도록, `countNotes` 및 탭을 가정했을 수 있는 정확도·상태 위젯 점검 (위젯은 미확인).

### 7.4 주의
- 무한 트레이닝의 별점은 **sunnySR**(`SyntheticPatternMap.CalculateSunnySr`)이다. E4를 넣어도 트레이닝 화면의 숫자는 바닐라 SR처럼 오르지 않을 수 있다. 바닐라 SR 펌핑 확인용이면 별도 표시 경로가 필요하다.
