## 개인화 fit(PersonalFitSolver) ridge 버그 3연속 발견·수정 (2026-08-21)

실기 대조(정확도 96% 근처 실제 기록은 SR 7.2~7.8인데 모델 예측은 6.3~6.9대)로 시작해 ridge 관련 버그를 순차 발견:

- ridge penalty의 `n` 상한(100) 캡이 오히려 정규화를 ~4배 약화시키는 잘못된 수정이었음을 발견해 롤백(`ridge*n` 공식이 원래 n에 무관하게 상대강도를 유지하도록 설계돼 있었음)
- ridge penalty가 개인화 델타 11개에만 걸리고 beta엔 안 걸려 생기는 비대칭 편향(Jacobian 일부가 SR과 상관, 최대 0.50) 발견 → Jacobian을 [절편,SR0]에 직교화(FWL)하는 1차 수정
- 직교화가 raw Jacobian(평균≠0)에 그대로 내적되며 왼쪽 pill(개별 채보 SR)에 평균 -0.70의 새 균일편향을 만드는 걸 발견 → **최종 수정**: alpha/beta(SR0 단독 회귀, 이후 고정)와 개인화 11계수(그 잔차를 raw Jacobian에 ridge)를 완전히 분리한 2단계 설계로 `PersonalFitSolver.cs` 전면 재작성. 실측 검증: 평균편차 -0.70→-0.01, 방향분포 354/1→217/138
- 겸사겸사 Pool B 진입 문턱을 한때 "Performance 상대값"으로 바꿨다가(저SR 구간이 왜곡됨을 발견) 원래의 정확도 85% 고정 하한으로 재확정, Pool A는 순수 SR 대신 `ManiaPerformanceCalculator`형 Performance(SR^2.2×정확도배율) 기준으로 정렬 전환
- `PersonalSunnyWidget.cs`/`PersonalSunnyFitStore.cs` target 정확도 표시 96%→95%
- v6.5.2~6.5.7 순차 배포, 매 수정마다 실기 검증

## 열별 표준편차 정규화 ridge 시도 → 롤백 (2026-08-22)

95%대 정확도를 찍은 스트림 채보인데 개인화 SR이 만인보다 높게 나오는 제보. 원인은 `MixFirst`↔`PressingWeight`(같은 `StrainEvaluator` strain-mix 분기를 반대로 누름, r=-0.89) collinearity — 등방 ridge가 credit을 `MixFirst`에 몰아줌. 열별 표준편차로 정규화하는 방식을 시도해 held-out CV 개선(93/100 fold)까지 확인 후 v6.5.8 배포했으나, ridge 상수를 raw-jac 기준 그대로 써서 언클램프 해가 박스를 최대 6배 초과 → 클램프가 잘라내며 baked 350개 채보 전부(100%)에 -0.54 SR 균일 하락이라는 심각한 부작용 발생. `PersonalFitSolver.cs` Stage 2를 raw-jac 등방 ridge로 롤백(v6.5.9). ridge 재탐색·상관축 짝지음(fused) 페널티도 검토했으나 둘 다 held-out CV 기준 isotropic보다 못해 보류 — collinearity 자체는 실재하는 문제로 보이나 마땅한 해법을 아직 못 찾음.
